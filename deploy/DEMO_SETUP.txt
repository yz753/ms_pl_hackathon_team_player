TEAM PLAYER: SIMPLE DEMO SETUP

Judges: a hosted website is the simplest option. They open the supplied URL, choose a player and press Play. They should not need Python, uv, an Azure subscription or Azure CLI. Keep that hosted service available through judging. Localhost URLs only work on the machine running the application.

Developer reproduction (macOS, Windows PowerShell, Linux):
1. Install uv and open a terminal in the repository root.
2. Create the environment and install dependencies once:
   uv venv --python 3.12
   uv pip install --prerelease=allow -r requirements.txt
3. Install Azure CLI if needed:
   uv tool install --python 3.12 --prerelease=allow "azure-cli>=2.60"
   uv tool update-shell
   Restart the terminal if az is not recognised.
4. Sign into an account authorised for your Foundry project and Blob Storage:
   az login
5. Copy deploy/demo.env.example to deploy/demo.env and fill in the project settings. The developer's existing local deploy/demo.env is already filled in. Do not publish that local file or any credentials.
6. Start the viewer:
   uv run --no-project --env-file deploy/demo.env python scripts/run_demo.py

The same launch command works in Bash, zsh and PowerShell because uv reads the KEY=value file; it is not a shell script. Do not add export, $PWD or shell substitutions to that file. No environment activation or source command is required. Azure sign-in and permission setup are still necessary for a developer running their own copy; this is why a hosted URL is simpler for judges.

The launcher opens the correct recording/player after the server becomes ready. Keep the terminal running. Stop with Ctrl+C. If port 8001 is occupied, stop the previous viewer or append --port 8002. For configuration-only validation append --check; this does not test Azure connectivity.

Only public tracking enters the online analyser. Current-season reference analyses and recorded captions are for review and are not read as live results. Historical matches are retrieved from configured Azure Blob storage. Azure explanations require internet and may be withheld when evidence is insufficient or validation fails.

CURATED SEARCH: KEEP ONLY MATCHES THAT MEET THE REQUESTED CRITERIA
   uv run --no-project python scripts/search_curated_examples.py --workers 3

It resumes from runs/curated_2026_27/progress.json. By default it continues until all six criteria have candidate matches. Rejected matches and their analyses stay only in memory and are discarded, never written, uploaded or committed. Retained candidates still require visual and AI-narrative review. The progress file has aggregate counts and a resume cursor only. --max-trials 100 runs a bounded batch if desired; Ctrl+C stops the search. The search never changes the simulator, analyser or scoring configuration and never uploads to Azure.

The requested negative winger case is an accessible passing option that disappears during an off-ball run, followed by the attack being lost. The ordering alone is not proof the run caused the turnover. The existing live narration gate may not yet cover every newly discovered downside; do not label an offline review as a fully working live feature until checked.
